# Dota 2 CLI — Design Document

## 1. Опис проєкту
Dota 2 CLI — навчальний консольний застосунок для перегляду каталогу героїв Dota 2 та запуску простої покрокової текстової битви. Програма демонструє об'єктно-орієнтоване проєктування, розділення відповідальностей, командний інтерфейс і збереження даних у файлах JSON.

## 2. Мета та завдання
- Виводити каталог героїв і детальну інформацію про кожного героя.
- Показувати URL сторінки героя з графікою.
- Дозволяти створювати користувацьких героїв через діалог.
- Зберігати додані записи між запусками.
- Дозволяти вибирати двох героїв і проводити покроковий бій.
- Зберігати поточний стан бою та історію результатів.

## 3. Структура проєкту
### CLI — командний інтерфейс
`CommandLineInterface` розбирає введений рядок, знаходить потрібну команду та обробляє типові помилки. Інтерфейс `ICommand` описує назву, синтаксис, короткий опис і метод виконання команди. `ICommandStrategy` дозволяє групувати команди за функціями.

### Core — логіка програми
- `Hero` — модель героя: ID, ім'я, атрибут, тип атаки, здоров'я, сила атаки та URL графіки.
- `HeroCatalog` — пошук, перегляд і додавання героїв.
- `BattleGame` — запуск бою, обробка дій, зміна HP і визначення переможця.
- `GameState` — дані поточного або завершеного бою.

### Data — збереження
`JsonDataStore` завантажує та зберігає каталог і стан гри у JSON, а результати дописує у текстовий файл.

## 4. Детальний опис командного інтерфейсу
Програма запускається командою `dotnet run` і переходить у режим очікування `dota2>`. Користувач вводить команду та аргументи. Команди не залежать від регістру. `help` (також `--help` або `-h`, без урахування регістру) виводить перелік команд, `refresh` завантажує список героїв з OpenDota API, зберігає його в локальному JSON-файлі та додає користувацьких героїв, які не дублюються з віддаленим каталогом, а `exit` завершує роботу. Для `refresh` потрібне інтернет-з'єднання.

| Команда | Призначення |
|---|---|
| `refresh` | Завантажити список героїв з OpenDota API, оновити локальний каталог і зберегти користувацьких героїв, які не дублюються з віддаленими |
| `heroes` | Вивести всіх доступних героїв |
| `hero <id або ім'я>` | Показати характеристики та пряме URL-посилання на файл зображення; ім'я з пробілами можна взяти в лапки |
| `create` | Запустити діалог створення героя |
| `search <текст>` | Знайти героїв за ім'ям, ID, атрибутом або типом атаки |
| `play` | Показати доступних героїв і запитати вибір учасників через діалог |
| `play <id героя> <id суперника>` | Розпочати бій із заданими героями |
| `act attack` | Атакувати суперника |
| `act heal` | Відновити частину здоров'я |
| `act status` | Переглянути стан бою без витрати ходу |
| `status` | Вивести збережений стан останнього бою |
| `results` | Показати історію завершених боїв |
| `help` | Вивести довідку |
| `exit` | Завершити роботу |

### Створення героя
Команда `create` послідовно запитує ім'я, ID, атрибут, тип атаки, максимальне здоров'я, силу атаки та необов'язкове посилання на графіку. Атрибут і тип атаки перевіряються за дозволеним переліком. ID може містити латинські літери, цифри та дефіс. HP і сила атаки мають бути додатними цілими числами. Програма не дозволяє повторити ID або ім'я. Після успішного створення запис одразу зберігається.

### Ігровий цикл
Команда `play` показує доступних героїв і через діалог запитує ID гравця та суперника; також можна вказати їх одразу, наприклад `play axe lina`. Бій запускається між двома різними героями з каталогу. Після цього користувач може атакувати або відновлювати HP. Після дії гравця суперник завдає удару, якщо бій ще не завершився. Бій закінчується, коли HP одного з героїв дорівнює нулю. Після кожного ходу стан зберігається, а після завершення результат додається до історії.

### Формат виведення та помилки
Список героїв виводиться у вигляді рядків з ID, ім'ям, атрибутом і типом атаки. Детальна інформація включає пряме URL-посилання на файл зображення героя з CDN Dota 2. Консоль показує це посилання як текст; саме зображення в терміналі не вбудовується. Якщо команда або аргумент неправильні, користувач отримує повідомлення українською мовою замість аварійного завершення програми.

## 5. Моделі даних
`Hero`: `Id`, `Name`, `Attribute`, `AttackType`, `MaxHp`, `Attack`, `ArtworkUrl`.

`GameState`: `PlayerHeroId`, `OpponentHeroId`, `PlayerHp`, `OpponentHp`, `Turn`, `IsFinished`, `Result`.

## 6. Обмеження
Це навчальна текстова гра з тестовими характеристиками. Вона не запускає справжній матч, не підключається до акаунта Steam і не отримує актуальні ігрові характеристики. Посилання на графіку для стандартних героїв зберігається як прямий URL файлу зображення на CDN Dota 2.

## 7. Можливий розвиток
У майбутньому можна додати здібності героїв, ману, броню, випадкову шкоду, команди для редагування героя, автоматичні модульні тести та детальнішу перевірку доступності віддаленого API. Завантаження каталогу з відкритого джерела вже реалізовано командою `refresh`.
