# Перевірка застосунку

## 1\. Автоматизовані тести

Із кореневої папки проєкту виконайте:

```bash
dotnet run --project Tests/Dota2CLI.Tests.csproj
```

Очікуваний результат — `17/17 перевірок успішно`. Перевіряються парсинг відповіді OpenDota API, формула шкоди, порядок дій, лікування, захист, бойові профілі, збереження та відновлення гри, а також обробка некоректних даних.

## 2\. Перевірка графічного інтерфейсу

Для запуску з вихідного коду потрібні Windows і .NET 8 SDK. Команди нижче призначені для розробника:

```bash
dotnet restore Gui/Dota2GUI.csproj
dotnet run --project Gui/Dota2GUI.csproj
```

Перевірте такі сценарії:

1. Після запуску відкривається вікно з вкладками «Каталог персонажів» і «Бойова гра».
2. На вкладці каталогу відображається прокручуваний список карток. Картка містить портрет, ім'я, атрибут, тип атаки та бойові параметри.
3. Під час запуску застосунок автоматично намагається завантажити актуальний каталог з OpenDota API; кнопка «Оновити каталог» повторює запит. Для перевірки потрібне підключення до інтернету. Якщо мережа недоступна, мають залишитися видимими локальні персонажі.
4. На вкладці гри можна вибрати двох різних персонажів і натиснути «Почати бій».
5. Кнопки «Атакувати», «Лікуватися» та «Захищатися» змінюють стан гри, а повідомлення з'являються у текстовому полі.
6. Кнопки «Стан бою» та «Історія» виводять відповідну інформацію.
7. Кнопка «Зберегти як…» створює JSON-файл збереження.
8. Після початку іншого бою кнопка «Вибрати та завантажити сейв…» дозволяє вибрати попередній JSON-файл і відновити стан.
9. Після перезапуску застосунку останній автоматично збережений бій відновлюється.

## 3\. Перевірка готового EXE-файлу (розгортання)

Для перевірки версії, яку отримує кінцевий користувач:

1. Переконайтеся, що після публікації існує `Dota2GUI.exe` (у цьому проєкті файл може бути в `publish\\\\win-x64` або в `release/Dota2GUI` — залежно від використаного способу збірки).
2. Запустіть `Dota2GUI.exe` подвійним клацанням із Провідника Windows.
3. Переконайтеся, що відкривається графічне вікно з вкладками «Каталог персонажів» і «Бойова гра».
4. Перевірте основні сценарії з розділу 2: перегляд/оновлення каталогу, початок бою, дії, збереження та завантаження.
5. Переконайтеся, що для запуску готового автономного EXE-файлу не потрібно окремо встановлювати .NET Runtime.

Для кінцевого користувача потрібна Windows x64. .NET 8 SDK потрібен для збирання з вихідного коду, але не для запуску вже опублікованого self-contained EXE.

## 4\. Перевірка попередньої консольної версії

Консольний застосунок залишається доступним окремо:

```bash
dotnet run
```

Введіть `help`, щоб переглянути команди. Збереження CLI та GUI використовують спільну папку `%LOCALAPPDATA%\\Dota2CLI`.

## 5\. Збірка

Для перевірки обох проєктів у Windows виконайте:

```bash
dotnet build Dota2CLI.csproj
dotnet build Gui/Dota2GUI.csproj
dotnet run --project Tests/Dota2CLI.Tests.csproj
```
