# Перевірка практичного заняття 14

## 1. Автоматизовані тести

З кореневої папки проєкту виконайте:

```bash
dotnet run --project Tests/Dota2CLI.Tests.csproj
```

Очікується 8 успішних перевірок:

1. Парсинг JSON OpenDota API та підготовка моделі персонажа.
2. Формула шкоди, броня та межі Resist.
3. Персонаж зі Speed 150 діє раніше за Speed 100.
4. Персонаж зі Speed 200 отримує дві дії; для пари 200/150 друга дія 200 відбувається після дії 150.
5. Лікування не перевищує MaxHp.
6. Захист зменшує наступний отриманий удар на 50% і споживається.
7. Бойовий профіль не змінюється після редагування запису каталогу.
8. Збереження/завантаження відновлює номер раунду, історію та профілі персонажів.

## 2. Ручний сценарій CLI

```text
help
heroes
hero axe
refresh
heroes
play axe lina
status
act attack
history
save
exit
```

Після повторного запуску:

```text
load
status
history
act defend
act heal
save
```

`refresh` потребує інтернету. Якщо API недоступне, локальний каталог має залишитися без змін.

## 3. Перевірка швидкості

Для наочного тесту створіть через `create` персонажів із різними Speed (або змініть значення в `Data/heroes.json` до початку бою):

- 100 проти 100 — по одній дії; при рівності першим діє гравець.
- 150 проти 100 — спочатку діє Speed 150, потім Speed 100.
- 200 проти 150 — послідовність: перша дія Speed 200, дія Speed 150, друга дія Speed 200.

Для перевірки саме порядку відкрийте `history`: записи мають містити номер раунду та порядковий номер дії.

## 4. Результати збірки

Після виконання `dotnet restore`, `dotnet build` і тестів збережіть скриншоти консолі з успішною збіркою та результатом тестів. У середовищі підготовки архіву .NET SDK недоступний, тому ці команди необхідно виконати локально у Visual Studio / терміналі з .NET 8 SDK.
